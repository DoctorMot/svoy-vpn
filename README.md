# Свой VPN

Установщик личного VPN на своём сервере: **VLESS + REALITY** (Xray) с защитой сервера и помощником для выдачи ключей. Запускается одной командой с компьютера на Windows, готовый профиль для Clash Verge кладёт на рабочий стол.

Сделан на основе идеи [IBR-new/vless](https://github.com/IBR-new/vless), но переписан заново и доработан под ситуацию в России на осень 2026 года (подробности — в разделе «Чем отличается от оригинала»).

## Что нужно

- **Сервер (VPS)** за границей: Ubuntu 22.04 / 24.04 или Debian 12 (лучше всего Ubuntu 24.04), 1 ядро, от 512 МБ памяти. Подойдёт самый дешёвый тариф. От хостера нужны IP, логин `root` и пароль.
- **Компьютер на Windows 10 / 11.** Ничего ставить не нужно: используется встроенный в Windows `ssh`.
- **Clash Verge Rev** для компьютера: [github.com/clash-verge-rev/clash-verge-rev/releases](https://github.com/clash-verge-rev/clash-verge-rev/releases).

## Установка

1. Скачай этот репозиторий: зелёная кнопка **Code → Download ZIP**, распакуй архив.
2. Если на компьютере запущен Clash Verge — закрой его (значок в трее → «Выход»).
3. Дважды щёлкни **`install.cmd`**. Если Windows предупредит о файле из интернета — «Выполнить» (или «Подробнее» → «Выполнить в любом случае»).
4. Введи IP сервера, затем пароль root. Пароль при вводе не виден — это нормально.
5. Обычно через 3–5 минут на рабочем столе появится **`vpn-clash.yaml`**. На только что созданном сервере — до 20–30 минут: сначала он сам ставит обновления системы, установщик ждёт и раз в минуту пишет, что жив.
6. Clash Verge → «Профили» → перетащи файл в окно и нажми на него, чтобы он стал активным.
7. «Настройки»: **«Режим TUN» — ВКЛ**, «Системный прокси» — ВЫКЛ. На вкладке «Прокси» режим **«Правила»**.
8. Открой [ipleak.net](https://ipleak.net) — там должен быть IP сервера.

**Одной командой** (в PowerShell, без скачивания архива):

```powershell
[Net.ServicePointManager]::SecurityProtocol='Tls12'; $f="$env:TEMP\vpn-install.ps1"; iwr -UseBasicParsing https://raw.githubusercontent.com/DoctorMot/svoy-vpn/main/install.ps1 -OutFile $f; powershell -NoProfile -ExecutionPolicy Bypass -File $f
```


Параметры `install.ps1` (все необязательные): `-Server 203.0.113.10`, `-Port 2222` (если у хостера SSH не на 22), `-Bridge 198.51.100.7` (режим «мост», см. ниже), `-BridgeSshPort 22`, `-BridgePorts 443` (или `443:8443` — порт моста:порт сервера), `-Reset` (выпустить новые ключи), `-Verify` (см. «Безопасность»).

## Два варианта: напрямую или через мост

1. **Напрямую** — устройство → сервер за рубежом → интернет. Основной вариант, всё выше — про него.
2. **Через мост** — устройство → сервер в России → сервер за рубежом → интернет. Помогает, если провайдер не пускает к **адресу** зарубежного сервера. Если провайдер распознаёт сам протокол VPN — не поможет: через мост идёт тот же протокол.

Мост **не может прочитать трафик**. На нём нет ни ключей, ни Xray — только правило ядра (nftables DNAT) в своей таблице `svoy_bridge`: «порт 443 моста → порт 443 зарубежного сервера». Устройство подключается к мосту с теми же ключами, REALITY идёт от устройства сразу до зарубежного сервера. Подменить сервер мост не может: клиент сверяет публичный ключ REALITY. Мост видит IP устройства, время и объём соединений, адрес зарубежного сервера и имя сайта-прикрытия (SNI) — не больше.

Настройка — тот же `install.cmd`, на первый вопрос ответь `2` (или `-Bridge IP_МОСТА`). Установщик по SSH настраивает мост (`server/bridge.sh`), затем обновляет зарубежный сервер и добавляет мост в список (`vpn bridge add`). Сервер сам проверяет связь через мост своим ключом. Если зарубежный сервер из твоей сети напрямую недоступен, установщик заходит на него через мост (`ssh -J`).

В профиле `vpn-clash.yaml` оба пути: группа `AUTO` типа `fallback` — основной путь напрямую, мост подхватывает сам, если прямой перестал отвечать. Мимо VPN при этом ничего не идёт: если недоступны и сервер, и мост, интернет пропадает.

**Риски.** Российский хостер может отключить мост без предупреждения: закон 210-ФЗ (2026) запрещает хостерам давать ресурсы для обхода блокировок. Сервер привязан к паспорту владельца. Поэтому прямой путь в профиле остаётся всегда.

## Что делает установщик

| Шаг | Что происходит |
|---|---|
| Проверка связи | До установки проверяет, доступен ли сервер из твоей сети. После — доступен ли порт VPN. Если нет, почти всегда виновата блокировка IP у провайдера: проси хостера сменить IP |
| 1. Сервер | Проверяет систему; если стоит панель 3x-ui, останавливается: ставить поверх нельзя |
| 2. Пакеты | curl, openssl, python3, qrencode, ufw, fail2ban, unattended-upgrades. Если система в этот момент сама ставит обновления — ждёт до 5 минут |
| 3. Xray | Официальный скрипт XTLS/Xray-install — закреплён на проверенном коммите и сверяется по SHA-256. **Версия Xray закреплена: v26.3.27**; архив Xray скрипт тоже сверяет по SHA-256 |
| 4. Ключи | Создаёт ключи REALITY. **При повторном запуске сохраняет старые** — ключи на устройствах продолжают работать |
| 5. Сайт-прикрытие | Перебирает незаблокированные в России сайты с TLS 1.3, HTTP/2 и сертификатом ECDSA. Speedtest (заблокирован с 30.07.2025), Cloudflare и Apple исключены. При повторном запуске прежний сайт сохраняется, если он не из этого списка |
| 6. Настройка | VLESS + REALITY + Vision на порту 443. DNS устройств обрабатывает сам сервер. Торренты и доступ в локальную сеть сервера закрыты. BBR, журналы хранятся 3 дня |
| 7. Защита | Firewall (открыты только SSH и порты VPN), fail2ban (5 неверных паролей — бан SSH на 10 минут), автоматические обновления безопасности |
| 8. Самопроверка | Пропускает через готовый VPN настоящий запрос. Если связи нет — сообщает, а не отдаёт нерабочий профиль |

Пароль root установщик **не меняет** и вход по паролю **не отключает** — сделай это сам: `passwd` на сервере.

Установка на сервере идёт отдельно от SSH-сессии: если связь оборвётся посередине, сервер доведёт её до конца сам, а повторный запуск дождётся окончания и заберёт профиль. Журнал каждого запуска — на сервере в `/root/.vpn-setup/run-*/log.txt`.

## После установки: ключи для других устройств

На сервере (`ssh root@IP_СЕРВЕРА`) работает помощник `vpn`:

| Команда | Что делает |
|---|---|
| `vpn status` | Всё ли работает: Xray, порты, версия, сайт-прикрытие, список ключей |
| `vpn add phone` | Новый ключ для устройства + ссылка и QR (для Happ, v2rayNG, INCY) |
| `vpn yaml phone` | Профиль-файл для **FlClash** (Android) и Clash Verge (второй компьютер) |
| `vpn link phone` / `vpn qr phone` | Показать ключ ещё раз |
| `vpn del phone` | Отозвать ключ — устройство сразу отключится |
| `vpn log phone` | Подключалось ли устройство и когда |
| `vpn dest` / `vpn dest auto` | Проверить / сменить сайт-прикрытие |
| `vpn dns` | Проверить DNS сервера; `vpn dns on/off` — сервер сам отвечает на DNS устройств (включено по умолчанию) |
| `vpn bridge list` / `add IP` / `del IP` | Мосты через российский сервер: узлы «через мост» в `vpn yaml` и `vpn link` |
| `vpn bridge test IP` | Сквозная проверка: сервер → мост → сервер → интернет, ключом сервера |
| `vpn qr phone IP_МОСТА` | QR ссылки через мост |
| `vpn version` | Версия «Свой VPN» на сервере |

**Android:** лучше всего работает **FlClash** ([releases](https://github.com/chen08209/FlClash/releases), файл `…-android-arm64-v8a.apk`) с профилем из `vpn yaml ИМЯ`. Внутри тот же движок, что у Clash Verge, поэтому он работает там, где у Happ не проходит DNS. Файл перенеси на телефон кабелем или себе в «Избранное» (потом удали сообщение: файл — это ключ).

Один ключ — одно устройство: так при потере телефона отзываешь один ключ, а не отключаешь всех.

## Обновление и повторный запуск

**Обновить сервер до новой версии** — скачай новую версию и запусти `install.cmd`. IP сервера установщик предложит из профиля на рабочем столе. Ключи, выданные доступы и профили на устройствах продолжают работать. В конце установщик пишет, с какой версии на какую обновил (`vpn version` на сервере). Есть мост — ответь на первый вопрос `2`: обновятся и мост, и сервер.

Запускать `install.cmd` повторно безопасно: ключи и выданные доступы сохраняются, обновляются настройки, помощник и защита. Так можно:

- обновить сервер до новой версии установщика (проверено на стенде: 1.0.0, 1.0.1, 1.0.2 → 1.1.0);
- **перевести сервер, поднятый скриптом IBR-new/vless**, на эту версию. Ключи сохранятся; если прикрытием был Speedtest, он сменится. Тогда телефоны нужно обновить: `vpn link ИМЯ` или `vpn yaml ИМЯ`;
- починить сервер после ручных экспериментов.

`-Reset` — новые ключи с нуля: все старые ссылки и профили перестанут работать.

После **смены IP** у хостера просто запусти установщик с новым IP: профиль для компьютера придёт новый, для телефонов выполни `vpn link ИМЯ` / `vpn yaml ИМЯ`. После **переустановки ОС** установщик предложит забыть старый отпечаток сервера.

## Чем отличается от оригинала

| | IBR-new/vless | Свой VPN |
|---|---|---|
| Что нужно на компьютере | Node.js + npm-пакет `ssh2` | Ничего, встроенный `ssh` Windows |
| Версия Xray | Последняя | Закреплена v26.3.27: в пре-релизах 26.9+ Xray перестал пускать клиентов на mihomo (Clash Verge, FlClash) |
| Сайт-прикрытие | Первый подходящий, обычно `www.speedtest.net` — **заблокирован в России** | Незаблокированные сайты; Speedtest, Cloudflare и Apple исключены |
| Порты | 443 и 8443 | Только 443: Xray предупреждает, что нестандартные порты чаще приводят к блокировке IP (на уже установленных серверах 8443 сохраняется) |
| Повторный запуск | Новые ключи — все устройства отключаются | Ключи сохраняются |
| Обрыв связи во время установки | Установка может прерваться на середине | Сервер доводит её до конца сам |
| Установщик Xray | Последняя версия скрипта из ветки main | Закреплённый коммит, сверка SHA-256 |
| Ключи для телефонов | Нет | Помощник `vpn`: ключ на каждое устройство, QR, профили, отзыв |
| Защита сервера | Нет | Firewall, fail2ban, автообновления безопасности |
| DNS телефонов | Идёт через сервер по UDP | Сервер отвечает сам |
| Торренты / локальная сеть сервера | Разрешены | Закрыты |

Код оригинала (версия 1.2.0) проверен: вредоносного в нём нет, пароль используется только для входа по SSH. Отказ от него — ради независимости от npm-пакетов и чужих обновлений.

## Безопасность

- **Что скачивается.** На компьютер — ничего. На сервер — пакеты из репозиториев Ubuntu/Debian и Xray с GitHub официальным скриптом XTLS (скрипт закреплён на коммите и сверяется по SHA-256, архив Xray — тоже). Больше ниоткуда.
- **Где пароль.** Пароль root вводится только в окно `ssh` Windows и нигде не сохраняется.
- **Где ключи.** На сервере в `/root/vpn-keys` (доступ только у root) и в профилях на твоих устройствах. Никому их не пересылай.
- **Проверка файлов.** Серверная часть (`server/setup.sh`, `server/vpn`, `server/bridge.sh`) вшита в `install.ps1`, чтобы установщик был одним файлом. Убедиться, что вшито ровно то, что лежит в папке `server`, можно командой:

  ```powershell
  powershell -ExecutionPolicy Bypass -File install.ps1 -Verify
  ```

  На сервере пакет дополнительно сверяется по SHA-256 перед запуском.
- **Журнал подключений** (нужен для `vpn log`) хранится 3 дня.
- **На мосту** нет ключей и Xray, журнал firewall выключен, журнал системы хранится только в памяти. На мост уходит только `server/bridge.sh`.

## Если что-то не работает

- **«До сервера не доходят пакеты»** — IP заблокирован провайдером. Попроси хостера сменить IP, запусти установщик снова. Или настрой мост через российский сервер (режим `2`).
- **«Permission denied»** — неверный пароль root. Проверь раскладку и Caps Lock.
- **В режиме «Глобальный» Clash / FlClash показывает российский IP** — в профилях до версии 1.0.2 группа GLOBAL по умолчанию выбирала DIRECT. Пользуйся режимом «Правила» или обнови сервер установщиком и заново сделай профиль: `vpn yaml ИМЯ`.
- **Окно «зависло», в заголовке «Выделить»** — в старой консоли Windows щелчок мышью по окну ставит вывод на паузу. Нажми Esc — вывод продолжится. Установку это не прерывает.
- **Долго стоит на шаге «[2/8] Пакеты»** — новый сервер сам ставит обновления системы. Установщик ждёт (до 45 минут) и раз в минуту пишет, сколько уже ждёт. Окно не закрывай.
- **«Connection closed» посреди установки** — оборвалась связь, чаще всего из-за включённого VPN. Закрой Clash Verge и запусти установщик снова: он дождётся, пока сервер закончит начатую установку, и заберёт профиль. Ключи сохранятся.
- **Компьютер: браузер работает, а другие программы нет** — не включён «Режим TUN». Если он не включается, в Clash Verge установи «Сервисный режим».
- **Телефон подключается, но сайты не открываются** — поставь FlClash с профилем из `vpn yaml ИМЯ`.
- **Работает на Wi-Fi, но не на мобильном** — мобильные операторы иногда включают «белые списки»; настройками сервера это не лечится.
- Всё остальное — `vpn status` на сервере покажет, что не так.

## Для разработчика

```
install.cmd          запуск двойным щелчком
install.ps1          установщик для Windows (собирается, не править руками)
server/setup.sh      серверная часть установки
server/vpn           помощник vpn
server/bridge.sh     мост через российский сервер (nftables DNAT, без Xray и ключей)
tools/install.ps1.in шаблон установщика
tools/build.py       сборка: python3 tools/build.py
VERSION              версия
```

После правки `server/*` или шаблона выполни `python3 tools/build.py`: он вшивает серверные файлы в `install.ps1` и пересчитывает контрольные суммы. Номер версии живёт в `VERSION`, `server/vpn` (`VPN_VERSION`) и `server/bridge.sh` (`VERSION`) — `build.py` проверяет, что они совпадают.
